# 饭票 AI 接口（fanpiao.ai/1）

让任何 AI、任何程序，都能帮用户把饭票填好：身高体重、目标、三餐在哪吃、预算、常吃的食物和补剂、体重记录，甚至排好某几天的饭。

饭票这边**只认数据，不认是谁写的**。不管是 DeepSeek、豆包、ChatGPT、Claude，还是你自己写的程序，只要按下面的格式写出一段 JSON，饭票就能导入。导入前一定会先给用户看「会改什么」，用户点「确认导入」才写进去，所以不会被偷偷改掉数据。

---

## 一、用户怎么用（三步）

1. 打开饭票 → **我的 → 让 AI 帮你填**（还没建档的新用户，在建档第一页底下也有这个入口）。
2. 点 **复制给 AI 的说明**，粘贴给任何 AI。这段说明里有格式、规则和饭票的内置食物表。AI 会先问你几个问题。
3. AI 最后会发一段用 `{` 开头的数据。整段复制回饭票（连着前后的说明文字一起粘也行），点 **看看要改什么** → **确认导入**。

如果已经在「我的 → AI 设置」里填了模型密钥，还可以不出 App：在同一页「直接让饭票里的 AI 写」里用大白话说你的情况，让它写。

---

## 二、三种把数据交给饭票的方法

| 方法 | 适合谁 | 写法 |
|---|---|---|
| 粘贴 | 聊天 AI、普通用户 | 把 JSON（可以带 \`\`\`json 代码块和前后文字）粘贴进「让 AI 帮你填」 |
| App 链接 | 能生成链接的程序、AI 助手、网页、二维码 | `fanpiao://import?data=<base64url>` 或 `fanpiao://import?json=<URL 编码的 JSON>` |
| 网页版链接 | 在浏览器里打开的饭票 | `index.html#ai-import=<base64url>` |

所有方法都只会**打开预览**，不会自动写入。

`data` 用的是 base64url：先把 JSON 按 UTF-8 编码，再做 base64，然后把 `+` 换成 `-`、`/` 换成 `_`，去掉末尾的 `=`。

JavaScript（Node 或浏览器）：

```js
const data = Buffer.from(JSON.stringify(pack)).toString("base64url");   // Node
const link = "fanpiao://import?data=" + data;
```

Python：

```python
import base64, json
data = base64.urlsafe_b64encode(json.dumps(pack, ensure_ascii=False).encode()).decode().rstrip("=")
link = "fanpiao://import?data=" + data
```

项目里也带了一个小工具：`node tools/fanpiao-link.mjs 数据.json`，会打印出链接。

> 聊天 AI 很难把长文字准确地转成 base64，所以让聊天 AI 直接输出 JSON、用户粘贴，是最稳的办法。链接适合程序生成。

## 三、数据格式

完整的机器可读定义：[`fanpiao-ai-1.schema.json`](fanpiao-ai-1.schema.json)（JSON Schema draft-07）。

所有字段都可以省略，只写要改的部分。唯一的例外：**还没建档的用户**，`profile` 里必须有 `sex`、`age`、`height`、`weight`。

```json
{
  "format": "fanpiao.ai/1",
  "profile": { "sex": "m", "age": 20, "height": 175, "weight": 65, "goal": "gain", "activity": 1.55 },
  "prefs": { "budget": 35, "snack": true, "modes": { "b": "out", "l": "out", "d": "cold" } },
  "foods": {
    "enable": ["egg", "milk", "c_rice", "c_meat", "c_veg", "banana"],
    "disable": ["chicken", "broccoli"],
    "add": [
      { "n": "某牌无糖豆浆粉", "u": "袋(30g)", "c": "奶和豆", "r": "dairy",
        "k": 128, "p": 9, "f": 4.5, "cb": 13, "na": 40, "fb": 2,
        "price": 1.2, "ck": 1, "s": "bs", "mx": 2 }
    ],
    "price": { "c_meat": 8 }
  },
  "weights": [{ "d": "2026-11-13", "kg": 65 }],
  "plan": {
    "date": "2026-11-13",
    "meals": {
      "b": [{ "id": "o_baozi", "qty": 2 }, { "id": "milk", "qty": 1 }],
      "l": [{ "id": "c_rice", "qty": 1 }, { "id": "c_meat", "qty": 1 }, { "id": "c_veg", "qty": 1 }],
      "d": [],
      "s": [{ "id": "某牌无糖豆浆粉", "qty": 1 }]
    },
    "tip": "一两句今天这样吃的要点"
  },
  "note": "给用户的一两句话，显示在预览里"
}
```

### profile 资料和目标

| 字段 | 取值 | 说明 |
|---|---|---|
| `sex` | `"m"` / `"f"` | 男 / 女。也认「男」「女」「male」「female」 |
| `age` | 14–90 | 岁 |
| `height` | 120–220 | 厘米 |
| `weight` | 30–250 | 公斤。变了而没写 `weights` 时，会顺手记一条今天的体重 |
| `goal` | `"gain"` / `"cut"` / `"keep"` | 增肌 / 减脂 / 保持。未满 18 岁的减脂会改成保持 |
| `activity` | 1.2 / 1.375 / 1.55 / 1.725 | 几乎不动 / 每周运动 1–3 次 / 3–5 次 / 6–7 次或体力工作。写别的数会取最近的一档；写 0–14 的整数当成「每周运动几次」 |
| `proteinPerKg` | 0.8–2.5 | 可选。每公斤体重吃多少克蛋白。不写就按目标默认（增肌 1.8、减脂 2.0、保持 1.4）。写 `null` 或 0 清掉 |
| `kcalOverride` | 男 1500–6000，女 1200–6000 | 可选。自己定每天热量，写了就不再自动算。一般别写 |
| `restKcal` | 800–4000 | 可选。手表上的静息千卡 |

### prefs 三餐和预算

| 字段 | 取值 | 说明 |
|---|---|---|
| `modes.b` / `modes.l` / `modes.d` | `"out"` / `"cold"` / `"cook"` | 早 / 午 / 晚饭怎么吃：食堂或外面买 / 不开火（只有热水、微波炉）/ 自己开火做 |
| `budget` | 0–1000 | 每天吃饭预算（元），0 = 不限 |
| `snack` | true / false | 要不要加餐 |

### foods 食物

| 字段 | 说明 |
|---|---|
| `enable` | 打开（勾上）的食物。写内置 id，或者已有食物的名称 |
| `disable` | 关掉的食物 |
| `only` | `true` = 除了 `enable` 和 `add` 里的，别的全部关掉 |
| `add` | 内置里没有的食物，最多 80 样。名称和已有的自己加的食物相同时，会更新那一样；和内置食物同名、单位也相同（或没写单位）时，会改那样内置食物的数值 |
| `price` | 改价格：`{"id 或名称": 元}` |

`add` 里每样食物（营养都是「每 1 个单位」的值）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `n` | 是 | 名称，最多 24 个字 |
| `k` `p` `f` `cb` | 是 | 千卡、蛋白 g、脂肪 g、碳水 g |
| `u` | | 单位，如 `勺(30g)`、`碗(300g)`。默认「份」 |
| `price` | | 1 个单位多少元。不写按 0 元算，并在预览里提醒 |
| `na` `fb` | | 钠 mg、膳食纤维 g |
| `c` | | 分类：主食 / 肉蛋水产 / 奶和豆 / 蔬菜 / 水果 / 坚果 / 速食 / 补剂 / 食堂外食。不写按 `r` 推 |
| `r` | | 角色：`staple` 主食 / `protein` 蛋白 / `dairy` 奶和豆浆 / `veg` 蔬菜 / `fruit` 水果 / `fat` 坚果油脂 / `meal` 一整份饭。不写按三大营养素推 |
| `s` | | 适合哪几餐：`b` 早 `l` 午 `d` 晚 `s` 加餐，如 `"bs"` |
| `ck` | | 0 即食 / 1 要热水 / 2 要开火 |
| `out` | | 是不是食堂或外面买的（「食堂外食」分类默认是） |
| `mx` | | 一天最多几个单位，默认 3 |
| `st` | | 每次加减多少：1、0.5 或 0.25，默认 1 |
| `v` | | 算多少克蔬菜。蔬菜不写默认 150 |
| `on` | | 加进来后勾不勾上，默认勾上 |

**排餐时怎么用这些食物**：「食堂」那一餐只用 `out` 为 true 的；「不开火」只用不是外食、`ck` ≤ 1 的；「自己做」只用不是外食的；加餐只用不是外食、`ck` ≤ 1 的。所以一样食物要出现在哪一餐，`s`、`out`、`ck` 要配得上。

### weights 体重记录

`[{"d": "YYYY-MM-DD", "kg": 60}]`。`d` 省略就是今天；同一天已经有记录会被替换；将来的日期会跳过。最多 400 条。

### today 今天

`{"activeKcal": 650, "modes": {"d": "cook"}}`：今天手表上的活动千卡（目标会跟着变）、今天临时换的吃法。

### plan 排好的饭（可选）

一个对象，或最多 7 个对象的数组。只收今天前后 7 天以内的。

- `date`：日期，省略是今天
- `meals.b / l / d / s`：早、午、晚、加餐，每项 `{"id": 内置 id 或 add 里的名称, "qty": 几个单位}`
- `tip`：一两句要点，显示在「今天」页

数量会按这样食物的 `st` 取整，最多到「一天最多」的 1.5 倍。那一天已经打勾（吃了）的会保留。

不写 `plan` 时，饭票会用自己的排餐按新设置排今天的饭（今天还没打勾的话）。

### 其他

- `format`：写 `"fanpiao.ai/1"`。写别的版本号会提醒「有些内容可能导不进来」
- `note`：给用户的话，最多 300 字，显示在预览里
- 不认识的字段会跳过，并在预览里列出来

## 四、饭票怎么检查数据

- 能读：纯 JSON、带 \`\`\`json 代码块的、前后有说明文字的、有中文引号或多余逗号的。
- 每个数字都会检查范围，不对的那一项不改，并在预览里说是哪项。
- 新食物的热量和「蛋白×4 + 碳水×4 + 脂肪×9」差得太多（超过 30%）会提醒核对包装。
- 写到了饭票没有的食物 id，会跳过并列出来。
- 导入后勾选的食物少于 6 样，会提醒可能排不出饭。
- 只合并，不清空：没写的部分保持原样。AI 密钥和云端账号永远不会被改。
- 粘贴的如果是「导出」的完整备份，会提示去「导出、导入」那里导入。

## 五、内置食物 id

完整的表（id、名称、单位、营养、价格）在「复制给 AI 的说明」里，也可以直接看 `www/js/foods.js`。常用的：

- 主食：`rice` 米饭、`bun` 馒头、`oats` 燕麦片、`bread_ww` 全麦面包、`sweetpotato` 红薯、`corn` 玉米、`noodle` 挂面
- 肉蛋：`egg` 鸡蛋、`chicken` 鸡胸肉（生）、`chicken_ready` 即食鸡胸肉、`beef` 瘦牛肉、`pork` 猪瘦肉、`fish` 鱼柳、`shrimp` 虾仁
- 奶豆：`milk` 纯牛奶、`yogurt` 无糖酸奶、`soymilk` 无糖豆浆、`tofu` 北豆腐
- 蔬果：`broccoli` 西兰花、`greens` 绿叶菜、`tomato` 番茄、`cucumber` 黄瓜、`banana` 香蕉、`apple` 苹果
- 补剂：`whey` 乳清蛋白粉、`protein_bar` 蛋白棒
- 食堂外食：`c_rice` 食堂米饭、`c_meat` 食堂荤菜、`c_veg` 食堂素菜、`c_weigh` 食堂称重肉菜、`o_baozi` 肉包子、`o_egg` 水煮蛋、`o_soymilk` 豆浆、`o_beefnoodle` 牛肉面、`o_salad` 鸡胸轻食沙拉

## 六、提醒

饭票给的是一般性的饮食参考，不是医疗建议。AI 写的营养数值可能不准，包装食品以营养成分表为准。有慢性病、在怀孕或哺乳、有进食障碍史的人，请先问医生或注册营养师。
